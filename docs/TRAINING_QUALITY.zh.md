# 训练质量与性能对照

## 流程

1. 冻结源码、模型规格、数据与 tokenizer 身份。
2. 对 forward/backward、非重入激活检查点、数值和缓存进行预检。
3. 在明确声明的确定性参考路径上做连续 8 步与重启 4+4 步对照，核验模型、Adam、随机状态、样本顺序、LR、sampler 和 scheduler。
4. 从同一 checkpoint 出发，用两个种子分别进行原版与加速版续训。相同全局 batch、样本、LR 和 token 预算。
5. 比较完整语料/外部参考 NLL、选择题、数学、代码与生成重复率。
6. 保留失败证据，记录测量是否完整以及可判定门禁是否通过，不自动采用优化。

## 一次有限测量的结果

一个约 1B 参数、32 层 GDN/GQA 混合模型的实验中，原版每卡 micro-batch=1、累积 4 次；加速版 micro-batch=4、累积 1 次，并使用 BF16 梯度通信、部分层激活检查点和 RMSNorm-only 融合。两组全局 batch 相同，长对照保留原快速卷积与原 DDP 配方。

两个种子各训练原版/加速版 1250 步，包含常规学习率段与高学习率压力段。排除前 10 步后，原版稳定训练吞吐约 18.6k–18.7k predicted token/s，加速版约 40.8k，对应约 2.18–2.19 倍。此口径不含 checkpoint 保存与终点评测开销。

两对全量语料 loss 差约 -0.000143 与 -0.000317，分域绝对差均低于冻结 0.03 阈值。总体绝对差阈值为 0.01；选择题下降阈值为 3 个百分点，生成重复 4-gram 增幅阈值为 5 个百分点。所有可判定门禁通过。

**局限不可省略：**

- 数学和代码 pilot 两版都为零分，必须列为不可判定，不能认证能力未退化。
- 生成的绝对重复率仍约 69%–73%，相对差通过不代表正常对话能力形成。
- 选择题每任务 256 条，数学 64 条、HumanEval/MBPP 各 64 条；这是探索性对照，不是无限总体等效性证明。
- 压力段之后两版验证 PPL 均高于起点，不能把加速版与原版相近解读为续训配方优越。
- 恢复一致仅在确定性 dweight＋固定 DDP 桶参考路径成立。原快速卷积、原动态 reducer 和从零训练质量均未取得无条件证书。

## EvalPlus 兼容性诊断

`training_eval_evalplus_compat_v6.py` 针对冻结 EvalPlus 0.3.1 的 `find_zero` 特殊 oracle 分支：成功后直接 `continue` 漏记 passing details/progress，导致 canonical 自检失败。修复仅在 worker 内补记状态；版本、原文件 SHA 和代码片段均校验，不改变 oracle、atol、输入、超时或安装依赖。

隔离回归覆盖官方 canonical 的 100 个 base、788 个 plus 输入，另一合法根、错误根及普通任务正反例。模型输出只在无网络、只读包、受资源上限约束的 namespace 沙箱执行。此补丁不应当被当作对任意 EvalPlus 版本的通用修复。

公开仓库仅包含脱敏代码与聚合说明，不包含 checkpoint、基准正文、原始模型生成或内部运行回执。
